用你已经熟悉的 Moderations 接口，跑自己的内容审核

基于 FastAPI 的网关，对外提供 POST /v1/moderations， 将打分路由到 Ollama Cloud 或自托管模型，并在上游异常时保持 失败闭锁（fail-closed）。

一句话：OpenAI 风格的内容审核 API + Ollama 推理。 通用对话模型做启发式风险评分，不等同于 OpenAI omni-moderation。支持多 Key 池、Docker； 上游失败时不会伪造 flagged=false。

工作原理

一条坦诚的薄管道：通用对话模型 + 结构化 JSON，再套上你的阈值。

1

客户端调用 Moderations

你的应用（或 OpenAI SDK）向网关发起请求，模型别名例如 moderation-fast。

2

网关对接 Ollama

原生 POST /api/chat，配合 JSON Schema 结构化输出。密钥轮换；鉴权/限流失败时进入冷却。

3

分数对照策略

启发式类别分数（0–1）与 configs/policy.yaml 比较。临界情况遵循你配置的 uncertain 模式。

模型别名

客户端 model Ollama 模型 说明
moderation-fast gpt-oss:20b 默认路径
moderation-standard gemma4:31b 更大推理预算
moderation-accurate gpt-oss:120b 最大；自托管需充足资源
omni-moderation-latest gpt-oss:20b 仅兼容别名 — 非 OpenAI 对等

与 sub2api 联调

真实场景：将 sub2api 的内容审计（风控中心 · 内容审计）指向本网关，作为 OpenAI 兼容的 Moderations 后端 — 同一套 /v1/moderations 约定，打分走你自己的 Ollama。

为何合适。 sub2api 期望 OpenAI 风格的 moderations Base URL。本网关说同一种方言， 因此可保留 sub2api 的风控界面，同时让推理落在 Ollama Cloud 或自有主机 — 无需另写客户端。

已验证的配置要点

1

Base URL — 不要带尾部 /v1

Base URL 请填 https://ollama-moderation-gateway.onrender.com， 不要追加 /v1。 sub2api 会自行拼接 /v1/moderations； 若再带 /v1 会变成 /v1/v1/...， 返回 {"detail":"Not Found"}。

2

模型

使用 moderation-fast （或兼容别名 omni-moderation-latest）。

3

API Key = 网关密钥

填写网关的 MODERATION_API_KEY， 不是 Ollama Cloud 密钥。 文档占位符为 your-gateway-api-key — 公开演示站可能需要你自行部署并配置密钥。

4

将 timeout_ms 提到 30000

默认 3000 对云端 LLM 延迟 + Render 冷启动过短。 请将 timeout_ms 设为 30000（30 秒）。

提醒：分数来自通用对话模型的启发式风险估计 — 不等同于 OpenAI omni-moderation-latest。 上线前请用自己的流量做评估。

集成参考： github.com/Wei-Shaw/sub2api。 本页仅记录这一组已验证对接，不扩展其他产品列表。

重要：不等同于 OpenAI omni-moderation

打分使用通用对话模型，不是专用安全分类器。

  • category_scores 是启发式风险估计（0–1），不是校准后的概率。
  • 质量、分数尺度与行为均不同于 OpenAI omni-moderation-latest。
  • 生产前请按你的语言与风险画像评估（scripts/evaluate.py）。
