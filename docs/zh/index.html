几分钟对接 sub2api

最对口的场景： sub2api 的内容审计（风控中心 · 内容审计）本来就支持 OpenAI 风格 Moderations 后端。 本服务就是那个后端 —— 界面继续用 sub2api，打分走免费的 Ollama。

改一处就够。 保留 sub2api 的风控界面，把 Moderations 的 Base URL 指到本服务。 不用写新客户端、不用换协议 —— 背后换成免费的 Ollama AI 审核。

快速配置

1

Base URL — 不要带尾部 /v1

填 https://ollama-moderation-gateway.onrender.com， 不要再加 /v1。 sub2api 会自己拼 /v1/moderations；多写一层路径会 404。

2

模型

用 moderation-fast （界面若偏好别名，也可用 omni-moderation-latest）。

3

API Key = 网关密钥

填网关的 MODERATION_API_KEY， 不是 Ollama Cloud 密钥。 公开演示站可能需要你自行部署并配置密钥。

4

把 timeout_ms 设为 30000

默认 3000 对云端模型延迟和免费层冷启动太短。

sub2api： github.com/Wei-Shaw/sub2api

部署

单机用 Docker Compose。生产走 Kubernetes + Helm。 Render 上的地址只是演示 —— 会冷启动，不是生产路径。

⎈

Helm 部署到 Kubernetes

生产主路径。Chart 在 charts/ollama-moderation-gateway（v0.1.0）。先在集群外创建 Secret，再 helm upgrade --install。

▣

Docker Compose

把 .env.example 复制为 .env，填密钥，docker compose up --build。端口 8000。适合单机。

☁

Render 只是演示

onrender.com 用来试接口。免费层会冷启动。当真用时走 Helm（示例域名 moderation.example.com）。

Kubernetes + Helm

建议在 Chart 外创建 Secret —— 默认 secrets.create: false，此时必须提供 existingSecret。 镜像：ghcr.io/aaronyang0628/ollama-moderation-gateway:v0.1.0（GHCR；私有包可能需要 imagePullSecrets）。 代理相关环境变量默认为空；仅在集群需要出口代理时再设置（真实代理地址不要进公开仓库）。 Ingress 默认 nginx + cert-manager，主机名为占位符 moderation.example.com（请改成你自己的）。 

kubectl create namespace moderation
kubectl -n moderation create secret generic ollama-moderation-gateway \
  --from-literal=OLLAMA_API_KEYS='key1,key2' \
  --from-literal=MODERATION_API_KEYS='gw-key1,gw-key2'

helm upgrade --install ollama-moderation-gateway ./charts/ollama-moderation-gateway \
  -n moderation --create-namespace \
  --set secrets.create=false \
  --set secrets.existingSecret=ollama-moderation-gateway \
  --set ingress.hosts[0].host=moderation.example.com \
  --set ingress.tls[0].hosts[0]=moderation.example.com \
  --set ingress.tls[0].secretName=moderation.example.com-tls

冒烟：curl https://moderation.example.com/health， 再带网关 Bearer Key POST /v1/moderations。 Chart 说明： charts/ollama-moderation-gateway/README.md。

Docker Compose

cp .env.example .env
# 设置 MODERATION_API_KEY、OLLAMA_API_KEYS（Cloud）以及 APP_ENV=production
docker compose up --build

怎么接上

三步搞定，不讲架构课。

1

你的应用调用 Moderations

OpenAI SDK、sub2api、curl —— 凡是会请求 /v1/moderations 的都行。

2

网关去问 Ollama

Key 自动轮换。你选云端或自建。moderation-fast 等别名会映射到对应 Ollama 模型。

3

拿到熟悉的结果

OpenAI 风格的 flagged / 类别 / 分数，直接接进现有风控流程。

模型别名

你传入 Ollama 实际跑 说明
moderation-fast gpt-oss:20b 默认推荐
moderation-standard gemma4:31b 更重一点
moderation-accurate gpt-oss:120b 最大；自托管需要充足硬件
omni-moderation-latest gpt-oss:20b 仅名称兼容 — 非 OpenAI 质量
